# CivicID Project Documentation

Welcome to the **CivicID** technical documentation. This document provides a comprehensive overview of the application's architecture, component structure, data flow, and feature set.

---

## 🏗️ Application Architecture

CivicID is a modern web application built with **React** and **Vite**. It follows a feature-based folder structure to ensure scalability and maintainability.

### Core Technologies
- **React**: UI library for building components.
- **Redux Toolkit**: Centralized state management for authentication and global state.
- **React Router**: Client-side routing with role-based access control.
- **Tailwind CSS**: Utility-first CSS framework for premium, responsive designs.
- **Lucide React**: Modern and lightweight icon set.
- **React Phone Input 2**: Standardized international phone number input.

---

```text

```

## 🚦 Routing and Access Control (`router.jsx`)

The application uses **Role-Based Access Control (RBAC)**. Routes are protected using a `ProtectedRoute` component that checks the user's role stored in the Redux store.

- **Guest Routes**: Accessible to everyone (e.g., Landing Page).
- **Private Routes**: Require login and specific role:
    - `CITIZEN`: Dashboard, Profile, Household, Certificates.
    - `OFFICER`: Dashboard, Registry Search, Enrollment, Application Tasks.
    - `ADMIN`: Dashboard, Analytics, User Management, System Logs.

## 💠 Core Components (`src/components/`)

- **`Button.jsx`**: A reusable button component supporting different variants (primary, secondary, outline) and sizes.
- **`Input.jsx`**: Standardized text input with label and error support. Placeholders are disabled by default for a cleaner look.
- **`PhoneInput.jsx`**: A custom wrapper around `react-phone-input-2`, tailored to the project's red/yellow theme.
- **`Card.jsx`**: A versatile container for content, featuring standardized shadowing and padding.
- **`Modal.jsx`**: Accessible modal dialog for forms and confirmation prompts.
- **`Header.jsx`**: The main navigation bar, featuring dynamic navigation items based on the user's role and a profile management menu.
- **`Footer.jsx`**: standard footer with copyright information.
- **`Logo.jsx`**: The branded CivicID logo component.

## 📄 Pages and Features

### 1. Landing Page (`src/pages/LandingPage.jsx`)
The entry point of the app. It handles:
- **Hero Section**: Introduces the CivicID platform.
- **Authentication**: Seamless Sign In and Sign Up forms with validation.

### 2. Citizen Features (`src/features/citizen/`)
- **Dashboard**: High-level overview of the citizen's status.
- **Citizen Profile**: View and edit personal information (name, address, photo, etc.).
- **Household View**: Manage family members, add new relatives, and view household relationships.
- **Certificate Request**: Request official documents (Birth, Death, Income, Community, Residence certificates).

### 3. Census Officer Features (`src/features/census/`)
- **Officer Dashboard**: Overview of pending tasks and registry stats.
- **Registry Search**: Search the national database for citizens by ID or name.
- **Enrollment Form**: Comprehensive form to register new citizens in the system.
- **Application Processing**: Review, approve, or reject certificate requests.

### 4. Admin Features (`src/features/admin/`)
- **Admin Dashboard**: System-wide performance overview.
- **Analytics**: Data visualization of registration trends and service usage.
- **User Management**: Add, edit, or remove system users (Officers, Admins).
- **System Logs**: Detailed logs of application activity for auditing.

## 🛠️ Hooks and State Management

### Global State (`src/features/auth/authSlice.js`)
Redux Toolkit is used to manage the authentication state:
- **`user`**: Stores current user details (name, email).
- **`token`**: JWT or session token for auth persistence.
- **`role`**: The user's role (CITIZEN, OFFICER, ADMIN) which dictates UI visibility.
- **`isAuthenticated`**: Boolean flag for quick login checks.

### Logic Flow
1. **Login**: User submits credentials -> `loginSuccess` action updates state and `localStorage`.
2. **Persistence**: `initialState` reads token from `localStorage` on reload.
3. **Logout**: `logout` action clears state and `localStorage`, redirecting to home.
